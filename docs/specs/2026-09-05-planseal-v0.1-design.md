# PlanSeal v0.1 Design

Status: approved

## Problem

A human may review a saved Terraform or OpenTofu plan, but an automation or AI
agent can later present a different file, source revision, provider lockfile,
or action scope. A generic approval message does not prove that the artifact
being executed is the artifact that was reviewed.

## Decision

PlanSeal creates minimal evidence for a saved plan, signs the evidence digest
with an owner-controlled Ed25519 key, and verifies the complete binding before
offering an apply command. Execution is explicit and protected by a durable
single-use ledger.

The binding contains:

- the saved plan SHA-256;
- a digest of the current Git revision;
- the dependency lockfile SHA-256;
- the sorted resource-address and action pairs;
- the certificate audience, validity window, nonce, and signer key ID.

## Privacy boundary

PlanSeal reads plan JSON only in memory. Evidence contains resource addresses
and action names, but no provider configuration, attribute values, state,
environment variables, credentials, command output, absolute paths, or raw
plan JSON.

## Command surface

- `planseal inspect`: produce deterministic, sanitized evidence.
- `planseal keygen`: create an Ed25519 owner key pair.
- `planseal approve`: validate action policy and sign an evidence digest.
- `planseal verify`: verify signature, time, audience, and artifact binding.
- `planseal apply`: verify all inputs, preview by default, and execute only with
  `--execute` after atomically consuming the certificate nonce.

## Security invariants

1. Unknown or malformed inputs fail closed.
2. A certificate is valid for at most five minutes.
3. The certificate binds the complete canonical evidence document.
4. Delete and replacement actions require explicit approval.
5. Apply never creates a new plan.
6. Apply invokes a fixed argument vector without a shell.
7. A consumed certificate cannot authorize another execution.
8. A no-op plan can be inspected but cannot be applied through PlanSeal.

## Non-goals

- Hosting an approval service.
- Managing cloud credentials.
- Replacing Terraform, OpenTofu, policy-as-code, or CI environments.
- Protecting a host already controlled by an attacker.
- Touch ID, mobile approval, remote receivers, or multi-party approval in v0.1.
