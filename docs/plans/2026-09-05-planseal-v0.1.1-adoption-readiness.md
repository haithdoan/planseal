# PlanSeal v0.1.1 Adoption Readiness

## Goal

Make PlanSeal straightforward to install, independently reproducible with real
Terraform and OpenTofu binaries, and credible as a small security-oriented
open-source project without expanding its v0.1 security contract.

## Scope

- Add a synthetic, credential-free example and end-to-end compatibility test.
- Exercise real saved-plan inspection, approval, verification, and apply
  preview with Terraform and OpenTofu in CI.
- Pin GitHub Actions dependencies to verified immutable commit revisions.
- Improve public installation, fit, limitations, and discovery guidance.
- Prepare the existing Trusted Publishing path for the owner's PyPI gate.

## Non-goals

- No live infrastructure apply.
- No hosted service, remote receiver, multi-party approval, hardware key, or
  operating-system keychain capability.
- No evidence or certificate schema change.
- No real plan, state, credential, resource address, private path, or company
  context in source, tests, logs, or documentation.

## Checklist

### T1 — Real-tool compatibility evidence

- [ ] Add a minimal `terraform_data` example with no external provider or cloud
      dependency.
- [ ] Add an opt-in integration test that creates an isolated Git repository
      and exercises the complete preview-only workflow through the public CLI.
- [ ] Run the test locally with both Terraform and OpenTofu.
- [ ] Add a CI compatibility job for both tools without executing an apply.

### T2 — Workflow supply-chain hardening

- [ ] Resolve every GitHub Action tag to a verified upstream commit.
- [ ] Pin all workflow action references to full commit SHAs with readable
      version comments.
- [ ] Keep Dependabot updates enabled for GitHub Actions.

### T3 — Public adoption path

- [ ] Document `pipx`/PyPI installation while retaining a source-install path.
- [ ] Add a concise "use it / do not use it" boundary and a reproducible
      synthetic example to the documentation hub.
- [ ] Prepare an owner checklist for public repository topics and metadata.

### T4 — Packaging and owner gates

- [ ] Verify lint, format, typing, unit tests, integration tests, build, package
      metadata, and sensitive-content scans.
- [ ] Confirm the release remains a patch (`v0.1.1`) under the documented
      pre-1.0 policy.
- [ ] Hand off PyPI Trusted Publishing, repository metadata, push, and release
      as explicit owner actions.

### T5 — Closeout

- [ ] Record fresh verification evidence below.
- [ ] Mark this plan complete only after local implementation checks pass.

## Acceptance Criteria

- A clean environment can run the synthetic PlanSeal workflow with Terraform
  and OpenTofu through `apply` preview, never `apply --execute`.
- CI proves real-tool compatibility separately from the mocked unit suite.
- All workflow actions are immutable full-SHA references.
- The public docs explain installation, fit, limitations, and the synthetic
  reproduction without private context.
- The wheel and source distribution pass package validation and contain only
  intended public files.
- No external write or live infrastructure action occurs during implementation.

## Publication Boundary

This plan authorizes local source edits, local tests, local package builds, and
local Conventional Commits only. The owner separately performs Git push,
GitHub metadata changes, PyPI Trusted Publisher configuration, release PR
merge, tag/release publication, and any infrastructure action.
